

> Prinsip yang saya tanam di suite ini (biar selaras filosofi kamu): test bukan cuma “jalan/tidak”, tapi **diagnosa** — setiap kegagalan harus menunjuk *kontrak* mana yang patah (wire-format, shape 4D, arity↔type, stateful/stateless, determinisme). Dan saya **sengaja** masukkan bagian *panic-surface* sebagai test kelas khusus, karena menyembunyikannya = menipu laporan.

---

## 0. Pra-syarat yang WAJIB Jules cek dulu (5 menit, mencegah suite salah target)

Sebelum menulis satu test pun, Jules harus membaca disk (bukan asumsi) dan men-catat di laporan:

1. **Format plan = 9 byte/step** (`arity,type,id,in,in2,out`) — verifikasi dari field `CompiledStep` di `graph.rs` + const `ARITY_UNARY=1/ARITY_BINARY=2` (`pub(crate)`, jadi **di Rust pakai const ini; di JS pakai literal `1`/`2`**). Kalau disk ternyata masih 7-byte, STOP dan lapor — jangan paksa.
2. **float-bridge dispatch** hanya melayani `LAYER_LINEAR`; tipe lain → `Err "not yet supported"`. Itu *bukan* bug, itu test (`A27`).
3. **Panic-surface yang diketahui** (bukan `Result`): `SeBlockConfig::init` `assert!(channels>=reduction)`; `GhostModuleConfig::init` `assert!(out_channels%ratio==0)`; dan inisialisasi Burn dengan dimensi 0 pada beberapa layer. Ini di-test sebagai **`should_panic` / try-catch expecting throw**, BUKAN sebagai `Err`.
4. **Stateless** = `pool`,`shift`,`binary`: `get_state`→`[]`, `load_state`→`Ok(())`, `num_params`→`0`. Stateful = 7 lainnya.
5. Framework: Rust host = `#[cfg(test)]` (opsional `rstest`); Rust wasm = `wasm-bindgen-test` (`wasm-pack test --headless`); JS = `vitest`. Test bridge (`I*`) butuh `wasm-pack build` dulu.

## 2. KEBIJAKAN NUMERIK & DETERMINISME (wajib konsisten di semua test)

- **Toleransi f32**: default `abs ≤ 1e-5` ATAU `rel ≤ 1e-4`; untuk akumulasi panjang (matmul besar, ES 200 gen) longgarkan ke `abs ≤ 1e-3`. Catat epsilon per-op di laporan.
- **Seed tetap** untuk semua test stokastik: `{7, 42, 123, 999, 2026}`. Test konvergensi wajib lolos di **semua** seed ini (mendeteksi flakiness).
- **Tidak ada** `sleep`, tidak ada network, tidak ada `Math.random` tanpa seed, tidak ada urutan-dependen antar-test (tiap test bangun registry/objek sendiri).
- **Property-based (bonus, tidak menambah floor 600)**: `fast-check` untuk `Matrix.multiply` (asosiatif tidak, tapi `A·I==A`, `(A·B)ᵀ==Bᵀ·A`) dan `buildPlan` (roundtrip parse). Ini *pengganda* robustness, dilaporkan terpisah.

**Aturan penulisan laporan (“bagaimana”):**
- Satu fokus asersi per test; nama mengikuti `test_<modul>_<perilaku>_<kasus>`.

- Tiap test wajib men-tag **kontrak** yang dijaga (kolom “Kontrak”: wire-format / shape-4D / arity-type / stateful-stateless / determinism / float-bridge / panic-surface) — supaya kegagalan langsung terbaca “mesin mana yang patah”.

- Laporan **deterministik**: dua run pada commit sama → §0/§3/§7 identik (kecuali durasi).
